## 03. Database Auto-Create — Per-industry database management

**As the** ODOO DEMO OPERATOR \
**I want to** automatically create a dedicated Odoo database for each industry folder \
**In order to** keep data isolated per industry without manual database setup or compose.yml changes.

## Description

Previously, `seed_loader.py` required the `ODOO_DB` environment variable to know which
database to use, and `compose.yml` hardcoded `-d portage_demo -i portage_demo,sale` to
create a specific database at startup. This meant adding a new industry required manual
configuration.

Now each industry folder automatically gets its own database. The database name is
derived from the folder name: `seeds/aion/` → `aion_demo`, `seeds/portage/` →
`portage_demo`. If the database doesn't exist when `seed_loader.py` runs, it is created
automatically via the Odoo JSON-RPC API — no manual setup needed.

## How it works

```
seed_loader.py --industry aion
  │
  ├─ 1. Derive DB name: "aion" → "aion_demo"
  │
  ├─ 2. Check if database exists
  │      POST /jsonrpc → db_exist("aion_demo")
  │
  ├─ 3. If not exists:
  │      POST /jsonrpc → create_database(master_pass, "aion_demo", ...)
  │      Then: install_modules("aion_demo", ["sale"])
  │
  └─ 4. Proceed with normal seed (company config, accounting, etc.)
```

### JSON-RPC endpoints used

| Method | Endpoint | Purpose |
|---|---|---|
| `db.create_database` | `POST /jsonrpc` | Create a new Odoo database |
| `db.db_exist` | `POST /jsonrpc` | Check if database already exists |
| `ir.module.module` | `xmlrpc/2/object` | Install `sale` module after creation |

### Module installation

After `create_database`, the database has only `base` and core modules installed.
The `sale` module is required for invoice generation. It is installed automatically:

```python
def install_modules(db_name, module_names):
    uid = common.authenticate(db_name, 'admin', 'admin', {})
    for name in module_names:
        button_immediate_install([module_id])
```

The `account` module (required by `setup_accounting()`) is installed automatically
as a dependency of `sale`.

## Usage

### Basic — create database and seed

```bash
# No ODOO_DB needed — derived from folder name
python3 seed_loader.py --industry aion
# → Creates aion_demo, configures company, accounting

python3 seed_loader.py --industry portage
# → Creates portage_demo, configures company, partners, invoices
```

### Clean — drop and recreate

```bash
python3 seed_loader.py --industry aion --clean
# → Drops aion_demo entirely, recreates it, re-seeds
```

`--clean` no longer deletes records inside the database. It drops the entire
database via the PostgreSQL container and recreates it from scratch. This is
faster and avoids stale data issues.

### Override database name

The `ODOO_DB` env var is still honored as an explicit override:

```bash
ODOO_DB=custom_db python3 seed_loader.py --industry aion
```

### Override PostgreSQL container

For `--clean` to drop databases, the script needs to know the PostgreSQL container:

```bash
ODOO_DB_CONTAINER=my-postgres python3 seed_loader.py --industry aion --clean
```

Default: `odoo-demo-db-1`

## Implementation details

### `ensure_database(industry_name)`

Located in `seed_loader.py`. Called at the start of `run_industry_loader()`.
Sets the module-level `DB` global used by all subsequent Odoo operations.

```python
def ensure_database(industry_name):
    db_name = DB  # already set by run_industry_loader from industry name
    if db_exists(db_name):
        return
    create_database(master_pass, db_name, False, 'en_US', 'admin')
    install_modules(db_name, ['sale'])
```

### `drop_database(db_name)`

Terminates active PostgreSQL connections, then drops the database:

```python
def drop_database(db_name):
    # Terminate connections first
    docker exec psql -c "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname = '{db_name}'"
    # Then drop
    docker exec psql -c 'DROP DATABASE IF EXISTS "{db_name}"'
```

### `install_modules(db_name, module_names)`

Authenticates as `admin` on the new database, then installs each module:

```python
def install_modules(db_name, module_names):
    uid = common.authenticate(db_name, 'admin', 'admin', {})
    for name in module_names:
        button_immediate_install([module_id])
```

## Environment variables

| Variable | Default | Required | Description |
|---|---|---|---|
| `ODOO_URL` | `http://localhost:8069` | No | Odoo server URL |
| `ODOO_DB` | `{industry}_demo` | No | Override DB name (auto-derived from industry) |
| `ODOO_USER` | `admin` | No | Odoo user for XML-RPC |
| `ODOO_PASS` | `admin` | No | Odoo password |
| `ODOO_MASTER_PASSWORD` | `admin` | No | Odoo master password for `create_database` |
| `ODOO_DB_CONTAINER` | `odoo-demo-db-1` | No | PostgreSQL container name for `--clean` drops |

## Compose.yml changes

The `command` in `compose.yml` was simplified. It no longer hardcodes a database:

```yaml
# Before:
command: odoo -d portage_demo -i portage_demo,sale --db_host=db --db_user=odoo --db_password=odoo --without-demo=all

# After:
command: odoo --db_host=db --db_user=odoo --db_password=odoo --without-demo=all
```

Odoo starts without a database. The seed loader creates one when needed.
