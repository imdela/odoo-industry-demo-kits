## 02. Aion Seed — Odoo Demo Data for Visual Integration Test

**As the** VISUAL TEST EXECUTOR \
**I want to** seed Odoo with Aion-compatible demo data (accounting + invoices linked to synced companies) \
**In order to** run the full integration flow: Odoo → Bridge → Aion invoice ingestion.

## Automatic database management

Each industry folder gets its own Odoo database. The database name is derived from the
folder name: `seeds/aion/` → `aion_demo`, `seeds/portage/` → `portage_demo`.

If the database doesn't exist when `seed_loader.py` runs, it is **automatically created**
via the Odoo JSON-RPC API — no manual database setup needed.

## Architecture

```
seed_loader.py --industry aion [--clean] [--invoices]

Phases:
  1. seed --industry aion         → Creates `aion_demo` DB, company config, accounting
  2. Aion sync (US-32)            → Creates Odoo partners from Aion's Company entities
  3. seed --industry aion --invoices → Creates 20 posted invoices for the synced partners
```

### Database creation (automatic)

When you run `seed_loader.py --industry aion`, the script:
1. Checks if `aion_demo` exists via `db_exist` (JSON-RPC)
2. If not, creates it via `create_database(master_pass, 'aion_demo', ...)`
3. Installs the `sale` module (which pulls in `account`, `product`, etc.)

No manual `docker exec` or compose.yml changes needed.

### No `clients.json` or `developers.json` needed

Aion companies are created by the US-32 sync, not by the seed. Invoices are generated
for these synced partners. Client/developer demo data from `portage` industry is irrelevant
for this flow.

## Implementation

### Database creation (`ensure_database`)

```python
def ensure_database(industry_name):
    db_name = f'{industry_name}_demo'
    if not db_exists(db_name):
        create_database(master_pass, db_name)
        install_modules(db_name, ['sale'])
```

- Uses JSON-RPC `db.create_database` (Odoo 19 compatible)
- Master password from `ODOO_MASTER_PASSWORD` env var (default: `admin`)
- Installs `sale` module after creation to ensure all required models exist

### Clean flag (`--clean`)

Instead of deleting records within the database, `--clean` now drops the entire
database via PostgreSQL and recreates it:

1. Terminates active Odoo connections to the database
2. `DROP DATABASE IF EXISTS "{db_name}"`
3. `create_database(master_pass, db_name)` with `sale` module installation
4. Proceeds with normal seeding

### `_generate_invoices()` function

Extracted from the `portage` industry's transaction step. Takes `client_ids` and
`accounting_defaults`, creates 20 sale orders → confirms → generates account.move
→ posts.

### `--invoices` flag

When set, `run_industry_loader()`:
- Skips company config, partner import, resource import
- Calls `setup_accounting()` (idempotent via `search_or_create`)
- Queries existing partners: `is_company=True` and `id > 10`
- Generates 20 invoices for those partners

## Partner name matching

The bridge pushes invoices to Aion using `partner_name` from the Odoo invoice.
Aion's `InvoiceService::ingest()` does NOT currently resolve `partner_name` to a
Company — invoices are stored with `companyId` from the API key context.
The partner names must match Aion's Company entity names for correct matching
during future expansion.
